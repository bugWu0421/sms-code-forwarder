# 短信验证码转发 App · 使用手册

> 把安卓手机新收到的验证码短信实时转发到飞书群（推荐）或你自己的 HTTP 接口。
> 本手册面向直接安装 APK 的使用者。App 约 800KB，无任何第三方依赖，不采集任何数据。

---

## 一、安装

1. 把压缩包里的 `短信验证码转发.apk` 传到安卓手机（微信文件传输助手/网盘/数据线均可）
2. 点开安装，系统提示"未知来源应用"时选择**允许**
3. 需要安卓 7.0 及以上；**iPhone 不支持**（苹果系统不允许第三方读短信）
4. 首次安装后如果手机提示"该应用是为旧版本安卓设计"，忽略即可，不影响使用

## 二、首次配置（App 界面从上到下）

| 步骤 | 操作 |
|---|---|
| ① 授权短信权限 | 点「授权短信权限」按钮，短信/通知权限全部允许 |
| ② 电池白名单 | 点「加入电池优化白名单」按钮，选允许 |
| ③ 允许自启动 | 点第三个按钮（v1.4 起按本机品牌自动显示对应说明，一键直达该品牌的自启动/后台管理页）；国产手机必做 |
| ④ 转发目标 | 选「飞书机器人」（推荐，跟着《飞书接入手册.md》配 5 分钟）或「自定义接口」 |
| ⑤ 填地址 | URL 框粘贴 Webhook 地址；密钥框填签名密钥（飞书加签）或接口密钥 |
| ⑥ 测试 | 点「发送测试」，确认目标端能收到 |
| ⑦ 开总开关 + 保存 | 打开「总开关」，点「**保存设置**」（v1.1 起切出界面也会自动保存）。下方状态区会显示「**当前生效配置（从存储实测）**」，**以它为准**——总开关显示"开 ✅"才是真的生效 |

> **国产手机必做第③步**：华为/荣耀是"应用启动管理→关闭自动管理→三个开关全开"；小米/红米是"自启动 + 省电策略无限制 + 锁定后台"；OPPO/vivo/三星各有对应页，点 App 里的按钮会自动跳到本机品牌对应的设置页（找不到专属页面时会退到应用详情页）。
> 不做这一步，息屏、清理后台或重启手机后就不会转发——国产 ROM 默认拦截第三方应用的后台唤醒，任何 App 都绕不过，必须手动开一次。原生 Android/Pixel 无需此步。

## 三、转发规则

- 默认**只转发验证码类短信**：内容含「验证码/校验码/动态码/动态密码/确认码/verification code/OTP」或 `G-xxxxxx` 格式
- App 会自动从短信中提取验证码数字（4~8 位），单独展示一行，方便一眼看到
- 关闭「仅转发验证码类短信」开关 = 转发**所有**新收到的短信
- 同一条短信 10 分钟内只转发一次（自动去重，防运营商/双卡重发）
- 长短信自动拼接完整内容

## 四、自定义接口模式（给有服务器的同学）

App 收到短信后向你填的 URL 发起：

```
POST <你的URL>
Content-Type: application/json
Authorization: Bearer <你填的密钥>   ← 密钥留空则不带此头
```

```json
{
  "type": "sms",
  "from": "1069012345678",
  "code": "123456",
  "body": "【京东】您的验证码为123456，10分钟内有效",
  "receivedAt": 1760000000000,
  "receivedAtText": "2026-10-19 12:30:45",
  "device": "HUAWEI ALT-AL10"
}
```

`code` 仅在识别为验证码短信时存在。测试消息的 `from` 为 `"test"`。

**服务端必须校验 Authorization**，否则公网上任何人都能往你接口伪造数据。最小接收端（Python Flask）：

```python
from flask import Flask, request, jsonify
app = Flask(__name__)

@app.route("/api/sms", methods=["POST"])
def sms():
    if request.headers.get("Authorization") != "Bearer 你的密钥":
        return jsonify(error="unauthorized"), 401
    d = request.get_json(force=True)
    print(f"{d.get('from')} -> {d.get('body')} 验证码:{d.get('code')}")
    return jsonify(ok=True)

app.run(host="0.0.0.0", port=8000)
```

## 五、后台保活（重要！各品牌手机必做）

转发依赖系统把新短信广播给 App，国产手机默认会冻结后台应用，必须放行：

| 品牌 | 路径 |
|---|---|
| **华为/荣耀** | 设置 → 应用和服务 → 应用启动管理 → 本应用 → 关闭「自动管理」→ **允许自启动/关联启动/后台活动 三个全开** |
| **小米/红米** | 设置 → 应用设置 → 应用管理 → 本应用 → 允许「自启动」；省电策略 → 无限制；最近任务界面下拉本应用卡片「锁定」 |
| **OPPO/一加/真我** | 设置 → 电池 → 更多设置/应用速冻 → 关闭本应用的「智能速冻」；允许自启动、后台运行 |
| **vivo/iQOO** | 设置 → 电池 → 后台高耗电 → 允许本应用；应用管理 → 权限 → 关联启动允许 |
| **三星** | 设置 → 电池 → 后台使用限制 → 把本应用从"深度睡眠"列表排除 |
| **原生/Pixel** | 无需额外设置 |

**通用红线**：不要在最近任务里「强制停止/深度清理」本应用——强停后系统不再投递短信广播，需要重新打开一次 App 才恢复。

## 六、常驻服务与开机自启（v1.2+）

- 配置完成后，通知栏会出现「**短信验证码转发运行中**」常驻通知（最低优先级，无声不弹窗）。这是保活机制：有它在前台，息屏、清理后台都不会影响收短信。**不要隐藏后强制清理它**
- **重启手机后自动恢复转发**（开机自启），无需打开 App——前提是完成了上面的"允许自启动"设置
- **v1.4 起**：转发失败（弱网/息屏瞬间断网/服务端 5xx）自动间隔 2 秒重试，最多 3 次；Webhook 密钥经 Android Keystore 加密存储，升级后首次打开 App 会自动把旧明文密钥升级为密文
- 开发者联调可以不花话费模拟短信：
  ```bash
  adb shell am broadcast -a com.wj.smsforwarder.SIMULATE_SMS \
    --es from 10086 --es body "【测试】您的验证码是123456，10分钟内有效"
  ```
  它走与真实短信完全相同的过滤/去重/转发链路（v1.4 起仅 adb/系统/本应用可触发，第三方 App 伪造无效）

## 七、耗电说明

无轮询、无唤醒锁、无后台心跳流量：平时仅由一条最低优先级的常驻通知挂着前台服务（Android 8+ 对这类服务几乎零开销），短信到达瞬间被系统唤醒、发一个几 KB 的 HTTPS 请求（1~2 秒，失败最多重试 3 次）即完成。对续航无可感知影响。

## 八、收不到转发？排查清单（按顺序）

1. 通知栏是否有「短信验证码转发运行中」常驻通知？没有就打开一次 App（重启后也没自动出现 = 自启动没开，见第二节华为/荣耀必做）

1. 打开 App 看状态区「当前生效配置」：总开关是否为「开 ✅」、URL 是否已设置？这是从存储读出的真实状态，以它为准（v1.1 起切出界面会自动保存，无需手动点保存）
2. App 底部「最近一次转发记录」：
   - **无新记录** → 广播没进来：检查第五节后台保活设置；是否被强制停止过（重新打开 App）
   - **有记录且报错** → 对照《飞书接入手册.md》错误码表（飞书模式）或检查接口地址/密钥
3. 验证码短信是否真的符合关键词规则？（普通聊天消息默认不转发，可关掉「仅转发」验证）
4. 换个网络（WiFi↔流量）再测一次
5. 重启手机后再测一次

## 九、安全须知

- 验证码短信是账号资产的钥匙，**只转发到自己控制的飞书群/接口**
- 飞书模式：**每人配自己的机器人和群**，多人共用同一个 Webhook 等于互相暴露验证码
- 自定义接口模式：服务端必须校验密钥 + 用 HTTPS
- 本 App 所有配置仅保存在手机本地，无任何数据采集、无任何第三方 SDK
- 不用了直接卸载即可，无残留
